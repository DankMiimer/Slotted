## Room surfaces (22 October, editor revision 12)

In **Room studio > Room positions & travel paths**, **Room surfaces** sets the floor, the
walls (back and both sides) and an optional ceiling. Each one is the original colour, a
plain colour, or a texture with a **Tint** (white keeps the texture as it is) and
**One texture repeat (mm)**: how much floor or wall one copy of the image covers.

- Built-in textures (wood planks, carpet, tiles, concrete, plaster, paint, brick, wood
  panels, wallpaper, ceiling tiles) are original and generated by
  `python tools/tabletop/make_surfaces.py` into `build/tabletop/assets/surfaces`
  (`start.ps1` regenerates them when missing).
- **Add your own texture...** imports a PNG, JPEG or WebP: the centre square is resized to
  1024 px and kept in `scene-layouts/surfaces/own-NAME.png`. A seamless (tileable) image
  hides the repeats.
- The preview uses the device's geometry and shader: each repeat is its own quad, because
  the scene shader clamps texture coordinates (labels crop with them).
- A room with surfaces is written as `SLOTWORLD2` (`surface KIND R G B TILE TEXTURE|-`
  records); one without stays byte-identical `SLOTWORLD1`. Upload sends only the
  textures the room uses, to `_slot/tabletop/surfaces/`, and refuses (before changing
  anything) unless the recorded frontend declares `SLOTWORLD2` and its binary carries
  `SLOTTED_ROOM1:SLOTHOME1,SLOTWORLD1,SLOTWORLD2` (frontend `a1780e4a...` and later). A
  missing texture on the device falls back to the original colour.

## Room studio (21 October)

Open **Room studio** from the console editor for fixed room table positions,
travel paths, the full-model home table and its separate whole-TV camera.
Existing console JSON, camera views, browser drafts and history stay separate.
Room/home undo, drafts, reload recovery, explicit framing and JSON import/export
work locally. Device scene import is read-only and opens an undoable browser draft.
Importing does not replace the saved scene; Save keeps SHA-verified history and
refuses a stale editor overwrite. Home model pickers switch SNES PAL/US and
Mega Drive/Japan while preserving the authored placement and cameras.

**Save and upload to Slotted** uses the same single snapshot/apply/verify/restart
transaction as console batches. The console editor's Upload� dialog also includes
saved room/home scenes. CLI example:
`python -m tools.tabletop.editor.upload --layout room --layout home-panasonic --layout gba-pvm --open normal`.
Room/home scenes require the Slotted theme and a hash-verified frontend with the
`SLOTTED_ROOM1:SLOTHOME1,SLOTWORLD1` capability. Both host and device reject an
old binary/legacy-theme request before stopping the frontend or changing assets.
`room.world`, `home-TV.scene` and existing `SYSTEM-TV.scene` retain independent
native formats. Shared current runtime models are deduplicated; originals and
archives are never upload inputs. A mixed room/home/console batch is device-tested:
three changed scenes, 266 files verified; a forced failure after restart rolled
all three back with a clean audit. See TABLETOP_HANDOFF.md for exact trial state.

Slotted's current controls use four-direction physical selection, A insert then
a separate A launch, B eject/back, L2/R2 system switching and R3 authored cameras.
Object motion in Slotted can be Full or Reduced. Reduced keeps a small steady
selection highlight and removes idle sway, rocking and landing bounce. Saved
cameras and authored room travel paths keep their exact endpoints.
The older controls described below apply to the retained Art Book frontend.

# Scene studio

Double-click **Open Scene Editor.cmd** or open **http://127.0.0.1:8765** after
starting `powershell -File tools/tabletop/editor/start.ps1`. The hidden local
server remains available for later edits. All source geometry stays intact.

Batch upload and device import follow the active `Slotted` or `art-book-slot` theme.
They share the retained local models, while each theme keeps its own device layouts.
The transaction refuses a theme change after its initial comparison. Editor revision
8 restarts an older local server on launch so the batch API is actually available;
saved layouts and browser drafts are retained.

The plain address reopens the console and TV you used last. Switching **Console**
keeps the TV when that pair has a saved layout, otherwise it opens the TV that
console was saved with (a GBA + PVM layout looked lost when SNES + Panasonic opened
and GBA was picked on Panasonic). An unsaved pair links to the saved one.

Choose a **Console** and **Television model** in the header. SNES, N64, NES,
Mega Drive, PlayStation, GB, GBC, GBA SP, DS Lite, PSP and PICO-8 are supported,
with Panasonic, PVM and Old TV profiles. The local NeilVFX SP remains the default
when present, matching the renderer; DS housing/card scales remain independent.

## Cameras

**Edit / preview view** selects Everything, Straight at the TV, Selected hovering
cartridge, Console close-up, or Free model movement (L3). Every view remembers its
own eye, target and FOV. Adjust them with the existing numeric controls or camera
orbit/pan/dolly. Switching views pans smoothly; **Pan time** sets 0.1-5 seconds.
**Default browsing camera** sets the opening device view.

For an explicit manual setup, select the desired **Edit / preview view**, enter
camera XYZ, look-at XYZ and **Exact FOV**, then click **Apply camera to this view**.
The active view is named above the fields; other camera views retain their own
values. Numeric edits preview immediately and participate in Undo/Redo. Editing
during a pan finishes that pan before applying your values, so it cannot overwrite
the new camera. **Adjust camera with mouse** enables orbit/pan/dolly with handles
out of the way; it also turns off model dragging in L3. Select a model or choose
Move/Rotate to return to object controls.

The overview always begins with your exact saved camera or newer browser draft.
Opening another view never reframes that overview. A previously unconfigured
close-up gets an initial framing; **Frame this view** explicitly replaces only
the currently selected view. The cartridge view follows the preview cartridge;
its authored camera is stored relative to cartridge 1 and follows selection on
the device. **Return to overview** uses the saved overview camera.
Selecting a cartridge object also selects it for the camera preview. A game that
is already inserted uses the console close-up, then pans back after ejection.

Close cameras never slice models open: the editor and the device both move the
near plane to just in front of the closest model in view (10-150 mm). In the
cartridge view, carts nearer the camera that would cover more than 2% of the
selected cart's label fade to a quarter so the label stays readable (judged at
the camera's destination; they return when the camera moves on). The overview,
TV and console views never fade anything.

In L3 preview, drag to turn the source model freely, or use the arrow keys.
Uncheck **Drag model** to orbit the camera instead. **Reset model turn** resets
only the temporary inspection rotation. **B** returns to the overview. Preview
hover and inspection never change the saved cartridge transforms.

On the device (n9 or later), a game that has finished slotting in pans out to the
overview while it is selected (unless a camera was picked with Select+R3). Starting
it pans to the console view and zooms into the handheld's screen (DS: top screen),
or for home consoles, and handhelds whose screen faces away from the console camera
(the face-down PSP) or have none (PICO-8), to the TV view and into the TV glass. The
power phase lasts the pan time, so the pan ends before the zoom starts.

Device controls: hold **Select** and press **R3** to cycle overview -> TV ->
selected cartridge -> console. Release and press R3 again for the next view.
R3 alone still toggles the carousel; L3 still opens inspection, D-pad turns, and
B/L3 returns. Select alone keeps options (short press) and favorites (long press,
now on release). Camera cycling is ignored during insertion/launch/inspection.

## Displays and furniture

**Display metadata** configures TV and handheld LCDs independently. Choose
visibility, artwork + text / full-width text / artwork-video, text scale,
padding, background, text and accent colours. Toggle title, HUD, box art/gallery,
description, game details, page indicator, video and library statistics.
**Preview page** selects a sample metadata page; native rendering uses the real
inserted game's metadata and the existing single video decoder.
L1/R1 advances each enabled display through its available pages. Text layouts
omit artwork/video pages; artwork layouts omit game-detail/library text pages.

Handheld LCDs remain blank by default. Enable them here to opt in. The actual
registered LCD corners are used, including both DS screens and the chosen local
SP. The TV remains the launch display. PSP rests face-down in its existing
insertion registration; its front display can be seen by rotating the console.

**Table model & size** chooses the original lena-wachs table, Qu3st10n's TV stand,
or AndreyUEDev's wooden table. Edit width, height and depth multipliers from
0.1 to 5. **Keep proportions** links them; uncheck it for independent dimensions.
The top surface remains at the table node's height. Furniture switches preserve
all hardware, cartridge and camera poses. The new furniture is narrower than the
original table, so arrange/scale it explicitly to support your chosen layout.
Use the Table object's existing position/rotation controls to place it.

Full 4k GLBs, original archives and SHA-256 source records are retained under
`research/tv-stand-qu3st10n` and `research/table-andrey`. Durable source/licence
records are in `third_party/models/qu3st10n-tv-stand` and
`third_party/models/andrey-wooden-table`. The TV stand is CC BY-NC-SA 4.0
(noncommercial, attribution, share alike); the wooden table is CC BY 4.0.
The stand's original zero-alpha collision proxy stays hidden and is retained.

## Arrangement, save and recovery

Click a model; **W** moves, **E** rotates. Use handles or exact millimetres/degrees.
Use **Shift/Ctrl-click** (Cmd-click on macOS) in the model list or viewport to
add/remove objects, or enable **Select multiple** for ordinary toggle clicks.
The selected buttons and count show the active set. **Clear selection** clears
it; **Select all objects** selects all sixteen nodes. **All cartridges** selects
the twelve cartridges together, with independent poses on save.

A multiple selection has one shared move/rotation handle at its center. Numeric
Position sets that center in world millimetres; Rotation turns the set around it.
Spacing, model scale and parent relationships remain intact. A TV plus its status
display moves once through the TV parent. Undo/Redo restores the complete edit.

For the quickest swap, select two objects and click **Swap selected pair**.
Alternatively, open **Swap two objects**, choose the pair and click **Swap transforms**. Selecting
exactly two objects fills the pair automatically. Position and Rotation can be
enabled independently. The action exchanges world positions/rotations, preserves
each model's size and hierarchy, and can be undone with one Undo.

Drag empty space to orbit; right-drag pans; wheel dollies. **F** focuses a model.
**Rest on table** grounds the selected model. Status remains relative to its TV.
Choose 3:2 or 4:3; horizontal camera framing is preserved for every camera view.

Undo/redo includes cameras, metadata and furniture settings. Browser drafts are
separate per system/TV; the original SNES draft key is retained. Before restoring
an existing draft for the first time, the editor also retains it under the same
key plus `-before-multiview`. Durable checkpoints/history remain untouched.

**Save layout** writes only `scene-layouts/SYSTEM-TV.json` and the
matching derived `build/tabletop/assets/layouts/SYSTEM-TV.scene`. Prior JSON
versions go to `scene-layouts/history`. **Export JSON** downloads a portable copy.
**Export preview PNG** captures the actual 3D viewport. **Reload saved layout**
restores the saved profile and keeps the previous browser draft under a dated
`-recovery-` key, with a SHA-256 copy check; Undo can restore it as well.
Eight-cart legacy profiles remain readable; the editor expands to twelve without
changing their original eight poses or camera. Systems without a profile borrow
the saved SNES layout using the native console/media height offsets.

**Copy layout to other consoles** → **Save for all TV consoles** (SNES, N64, NES,
Mega Drive, PlayStation) or **Save for all handheld consoles** (GB, GBC, GBA, DS,
PSP, PICO-8) saves the current layout with the same TV for each of them, the current
console included when it is in the group. Each console node is raised/lowered so its
base rests where the source console's did, carts so their media rest on the table, and
the console/cartridge cameras follow those offsets. A confirmation lists the consoles
and which saved layouts would be replaced; replaced files go to `scene-layouts/history`.
Fine-tune each console afterwards. Tick **…and upload them to the device** first to
send every layout just saved in one batch upload (below), opening the current layout
afterwards when it is in the group, otherwise normal startup. The server saves and
starts that batch under the upload lock, so while another upload runs it refuses
without saving anything.

**Import layout from device** (Device preview section) reads, over the same SSH
connection, the native layout the device renders for the current console and TV and
loads it into the editor as an undoable change (nothing on the device changes). If the
device has none for that pair, the editor lists the layouts it does have. Save keeps it.

**Import all from device…** reads every layout on the device in one SSH call and lists
those that differ from your saved layouts (or that have no saved layout here), all
ticked. Importing makes each one an unsaved browser draft for its console and TV:
the open layout changes through Undo; any other layout's existing draft is first kept
under its `-recovery-` key, and an `-import-undo` record lets Undo return to that
draft (or to the saved layout) when you open it. Save layout keeps an import. Nothing
on the device changes.

Saving is local. **Upload to device**, at the top right beside the console/TV
selectors, saves the current scene and opens it on the handheld. Connect the
handheld to Wi-Fi, return to the frontend, choose the console and TV, then click
Upload. There is no separate manual copy or frontend restart. Progress and the
verified recovery session appear below the button. An active game blocks upload.

**Upload…** (beside it) uploads several saved layouts at once. It lists every saved
`scene-layouts/SYSTEM-TV.json` and compares each with ONE SSH read of the device's
`.scene` hashes: **Same as device**, **Changed** or **Not on device** (the hash is of the
twelve-cartridge native file upload would install). Changed rows start ticked; the
Changed / Changed + new / All / None buttons retick. **Open afterwards** picks a saved
console/TV for the frontend to open, or normal startup. Only saved layouts are sent;
if the open layout has unsaved edits, **Save layout first** saves it and rechecks that
row without another device read. Upload refuses if a ticked layout was saved again
after the list was read (reopen Upload…). The quick **Upload to device** is the same
transaction for just the current layout.

All ticked layouts go in **one device transaction**: one fresh snapshot; one combined
manifest of every runtime file the layouts need, each listed once (a shared TV,
table or console model is checked and sent once); only files whose device hash differs
go into the single tar; one frontend restart; every needed file (sent or already
there) is hashed after install and again after the restart; one audit. If anything
fails, the whole snapshot is restored, so every layout and model rolls back together,
and the device reports each sent file as restored or removed. The dialog and header
show per-file progress (checking, already on device, to send, sent, received,
installed, verified, rolled back). The same job runs from the command line:
`python -m tools.tabletop.editor.upload --layout snes-panasonic --layout gba-pvm --open normal`
(`--open SYSTEM-TV`; `--fail-at installed|started` is a device-test hook that fails
there and rolls everything back).

Batch upload status (20 Oct 2026): **host-tested** (`tests/test_editor_upload.py`:
dedupe, unchanged-file skips, partial/corrupt/forced failures rolling back every file,
host and device locks, endpoints; dialogs browser-checked against a simulated device).
**Not yet device-tested**; see `docs/TABLETOP_HANDOFF.md` for the current state.

Uploads use the SSH target in `tools/dev/device.txt` (or `SLOT_DEVICE`) and the
existing configured SSH key. Each upload takes a fresh verified snapshot, installs
only the named native profiles plus required current model derivatives whose
hashes differ, and verifies the resulting files and data audit. Nothing is written
to the device before its read-only checks pass (frontend running, no game, ThemeSet).
A host lock refuses a second upload from the editor, and the device lock
`/userdata/system/slot-dev/editor-upload.lock` refuses a second transaction from any
host before it touches anything.

Current source runtime models are retained in the shared `art-book-slot/_slot`
asset tree. Read-only preflight selects the device's active supported theme,
Slotted or art-book-slot, and the worker rechecks it before stopping. The request
carries that exact target; snapshot/rollback covers both themes. It restores/audits
all current user data files before opening the preview; failure rolls the theme
back from that upload's snapshot and restarts the previous frontend. Source
models, alternatives, JSON history and browser drafts stay available. Edits made
while an upload is pending remain as a newer draft. An unchanged native scene
preserves the existing authored JSON bytes, including its line endings.

The preview uses process-only console/TV/model overrides. Normal startup, TV,
colour and alternative model preferences are preserved. The standard frontend
launch validation and A/Select+R3/L3/R3 controls remain in use. No game is launched
by upload. Upload now retains the compatible frontend by SHA-256 and installs a
small `/boot/postshare.sh` hook. Knulli activates that frontend after mounting the
data card, before its ordinary frontend startup; the firmware binary stays intact.
Reboot ends the console/TV preview and resumes normal startup/model preferences
with tabletop support still active. Saved scenes remain on the device. A missing
or corrupt retained binary, or changed firmware binary, leaves the firmware
frontend available and records the reason in
`/userdata/system/slot-dev/frontend-boot.json`. Native profiles reproduce authored transforms without automatic
fitting. The optional camera/table/display records require development build n
or later; process-only editor previews require n6 or later; the fitted near
plane, cartridge-view fading and faster rendering require n7 or later; n8 renders
with 4x MSAA and mipmapped labels instead of 2x supersampling.

Local evidence (each layout's JSON and native file under `layouts/`, the sent
manifest, the request with the full verification list, the tar and status) is retained at
`build/tabletop/editor-uploads/editor-TIMESTAMP-ID/`; matching device evidence is
under `/userdata/system/slot-dev/editor-uploads/`. Recovery snapshots are under
`/userdata/system/slot-dev/sessions/`. Upload status survives an editor restart;
an already dispatched device transaction continues independently. Do not reuse an
old snapshot to undo later gameplay or settings changes.

Each upload also retains the exact previous startup hook, frontend selection and
helper in its `startup-backup/`. Persistent binaries live under
`/userdata/system/slot-dev/frontend/` with hash-based filenames; older versions
remain available. Failed uploads restore the previous startup files as well as
the previous running frontend. The hook only activates the binary: Knulli's
normal init script still owns starting the frontend and launching games.

The uploader's compatible frontend is recorded with its SHA-256 in
`build/tabletop/editor-device/frontend.json`; the binary is kept beside it.
If rebuilding is necessary, apply `tools/frontend/apply.py` to the dedicated
source clone at the documented public pin, run `tools/frontend/build.sh`, strip
to a **new** binary filename, then update that JSON with its relative path and
SHA-256. Never overwrite the inode of a currently mounted development binary.

The loopback server exposes only explicit asset roots and requires its same-origin
session token and loopback Host/Origin for saves/uploads. Three.js 0.170.0 (MIT) is cached locally after official npm
SHA-512 verification. Startup recreates missing prepared assets from the preserved
sources and restarts a stale editor server after checking its PID/script identity.

## 3. Ordered implementation plan

The main risks are **source detail being lost in export**, **text becoming too
small inside real screens**, and **new geometry not fitting the old mechanisms**.
Downloading a larger file alone solves none of these. Judge each model on the
actual device, including motion. Keep the accepted reduced zoom; use the existing
pages and scrolling to expose more information without shrinking every field onto
one screen. Texture fidelity and the new TV profiles need common infrastructure
before repeated imports, which is why Phase A precedes the individual models.

### Phase A — Freeze the baseline and prepare a common asset pipeline

1. Read HANDOFF.md, TASK_QUEUE.md, CREDITS.md and this plan. Inspect the dirty
   workspace; preserve unrelated scraper/video work and existing model changes.
2. Snapshot the stopped device before new tests. Keep the current SP and accepted
   controls/layout as reference screenshots and regression cases.
3. Download the remaining originals/high-resolution conversions. Keep untouched
   masters with UVs, images, material assignments, names, animation/pivot data,
   hashes, author, licence and source URL. Import with Blender auto-execution
   disabled; inspect archives before extraction. Do not run source scripts/ROMs.
4. Establish semantic parts per source: enclosure, controls, glass, active LCD,
   bay, movable lid/door, spindle and any fixed source cartridge/disc to remove.
5. **Address texture support before repeating the earlier material loss.** The
   current native mesh is position/normal/vertex-colour only. Simply dropping new
   models through that exporter would remove their printed detail and materials.
   Plan a versioned UV/material extension or validated sidecars, retaining legacy
   meshes and the standalone helper. Preserve source base-colour information;
   assess normal/roughness support against measured device limits. Do not claim
   PBR fidelity if only albedo and simple lighting are implemented.
6. Measure actual GLES2 texture limits, memory and load time. Derive runtime
   texture/mesh budgets from final-size quality and hardware evidence. Preserve
   full masters; use per-part reduction only where needed. Do not apply one blanket
   13k-triangle collapse or upscale a small prerender. The present native format
   has 16-bit indices/65,535 vertices; PSP may need careful vertex/material splits
   or a backwards-compatible format extension.
7. Keep Realistic/Cel and the existing enclosure-colour choices working. Repainting
   must preserve screens, controls, labels/wordmarks and trim. Test source colours
   as well as an alternate paint choice; a multiplied green albedo is not a
   reliable implementation of every requested paint colour.

**Gate:** one prepared textured model can load, render and fall back safely,
with complete source/credit records and no regressions in existing models.

### Phase B — Integrate the selected GBC

1. Use BPoole's actual source. Preserve its silhouette, bevels, lens, controls,
   speaker and identifying texture detail. Avoid confusing source-material
   sampling with whole-model raster enlargement.
2. Assemble its separate battery cover: the imported source positions that cover
   far behind the housing. It must not float beside the console or inflate its
   presentation bounds. Keep a source-preserving master before this adjustment.
3. Remove the fixed source cartridge and use the existing independent complete
   Game Pak, dynamic ROM label and insertion path. Check the actual bay, contact
   direction, guide rails and fully seated depth through the complete animation.
4. Register the real LCD and blank its baked game screenshot. The source albedo
   atlas also contains a fixed Pokémon cartridge image; exclude unused source
   game art from prepared distributable textures. Retain original downloads intact.
5. Keep the half reading zoom and all metadata inside the LCD. Regenerate browse,
   animation and presentation views from the same registered source; do not show
   the old model during one phase of the sequence.

**Gate:** GBC slot/eject and idle/browse renders are consistent; cover is fitted;
no fixed Pokémon image remains; metadata aligns with glass and stays readable.

### Phase C — Add the TV theme setting and Retro TV

1. Add a global **TV model** theme subset/choice, preserving Panasonic as default.
   Initially provide Panasonic and Denys Hroshko's Retro TV. Reserve the kitnxi
   source in the queue, adding a real option only after its file is available.
2. Replace the hard-coded single-TV image/aspect/quad with a validated profile
